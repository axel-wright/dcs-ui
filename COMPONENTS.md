## Usage Pattern — the DCS init lifecycle

DCS has no build-time framework. Every component is a plain-JS controller
registered against a central registry in `js/dcs-core.js`.

1. **Register** — each `js/dcs-*.js` file calls
   `window.DCS.register('name', { init: function(el) { ... } })`.
2. **Mark up** — author HTML with `data-dcs-component="name"` on the root
   element of an instance.
3. **Init** — `DCS._init(container)` scans for
   `[data-dcs-component]:not([data-dcs-initialized])`, stamps each with
   `data-dcs-instance` + `data-dcs-initialized`, and invokes the
   controller's `init(el)`. It is idempotent — already-initialized nodes
   are skipped, so it is safe to call repeatedly (e.g. after injecting
   markup dynamically).
4. **Auto-init** — core fires `initAll()` on `DOMContentLoaded`, again on
   `window.load`, and once more after a 500 ms timeout to catch components
   registered late.

```html
<!-- Load order: core first, then any component scripts -->
<script src="js/dcs-core.js"></script>
<script src="js/dcs-modal.js"></script>

<div data-dcs-component="modal"> ... </div>
```

Shared helpers exposed on `window.DCS`:

- `DCS._trapFocus(container)` → traps Tab/Shift+Tab focus, returns a
  `release()` that restores focus to the trigger. Used by modal, drawer,
  bottom sheet, command palette.
- `DCS._focusable(container)` → visible focusable descendants in DOM order.
- `DCS._showToast(message, type)` → transient live-region toast
  (`type`: `info` \| `success` \| `warning` \| `error` \| `danger`).
